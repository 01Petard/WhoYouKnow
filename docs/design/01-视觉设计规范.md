# LinkMap-人脉本 · 视觉设计规范 v1.0

> **历史文档**：本规范记录 Phase 1 的设计结论。当前实现已改名为 WhoYouKnow，移除了好友状态、二级关系与查询页，并以分组 / 圈子 / 标签组织联系人。Token 与组件外观仍可参考；产品事实以 [`README.md`](../../README.md) 为准。

- 阶段：Phase 1 视觉方向设计
- 适用技术基线：React + Vite + TypeScript，本地优先响应式网页应用，localStorage/IndexedDB，无后端、无账号
- 主题：浅色（light）为默认且为本期唯一交付主题；所有颜色均通过语义 Token 间接引用，为将来扩展深色皮肤预留替换点
- 上游依据：`/docs/个人人脉管理应用PRD.md`
- 下游对接：体验与信息架构（Phase 2）、前端工程落地（Phase 3）

> 本规范只定义「看起来应该怎样」，不定义交互流程与组件代码。数值可直接转为 CSS 变量。

## 1. 美学方向（Aesthetic Direction）

### 1.1 三个关键词

**克制（Restrained）· 可信（Trustworthy）· 纸感（Tactile / Paper-like）**

| 关键词 | 含义 | 为什么契合本产品 |
| --- | --- | --- |
| 克制 | 界面不抢戏，信息是主角。单一强调色、无渐变、无动效噱头、无游戏化元素 | 这是一个单用户的私人工具，不是社交产品。用户来这里是「查一件事」「记一条关系」，需要快速进出，不需要被激励或娱乐 |
| 可信 | 视觉语言传达「这是一份由我亲自确认过的记录」，而不是「系统在猜」。结构清晰、状态可追溯、每个判断都有来源 | PRD 三条铁律：手动维护优先、不做复杂算法、隐私本地优先。视觉上必须避免任何暗示「AI 推断/智能推荐」的元素，否则会破坏用户对数据可靠性的信任 |
| 纸感 | 温润的米白纸底、极轻的卡片浮起、暖调墨色文字，像一本随时可以翻开的私人通讯录/手账 | 关系网是「养」出来的，用户会长期、反复地小剂量维护。温润、低刺激的材质感能降低长期使用的心理负担，也呼应「本地、私有、只属于我」的气质 |

**一句话气质**：像一本被认真维护的私人通讯录——安静、可靠、有温度，但绝不花哨。

### 1.2 视觉设计原则（5 条）

1. **内容优先于装饰**：任何视觉元素若不影响理解或操作，就删掉。不用装饰性插画、不用渐变背景。
2. **颜色从不单独承载含义**：四种好友状态（双向/单向/待确认/已失效）必须同时具备「颜色 + 文字标签 + 形状符号」三重编码，色觉障碍用户也能完整理解。
3. **状态即事实，不做真实性暗示**：状态徽章是小而克制的陈述标签，不是警告灯。禁止闪烁、脉冲动画、红点提醒。
4. **暖底 + 冷色强调**：页面与卡片用暖调中性色（米白/暖灰），唯一的高饱和强调色是墨蓝（操作）与四个语义色（状态）。这样强调色才真正「强调」得起来。
5. **一层深度原则**：界面最多只有「页面底 → 卡片」一层浮起关系。禁止卡片套卡片、多层阴影堆叠。

### 1.3 Do / Don't

**Do**
- 页面底色用暖米白 `#FBFAF9`，卡片用纯白 `#FFFFFF`，靠 1px 暖灰描边 + 极轻阴影区分层次。
- 墨蓝 `#325B8F` 作为唯一主操作色；导航激活、主按钮、链接都用它。
- 圆角 8–12px（弹窗/抽屉 16px），克制、不幼稚。
- 状态用「浅色底 + 同色系深字 + 6px 小圆点」的徽章，永远带文字。
- 留白充足：卡片间距 ≥12px，区块间距 ≥24px，正文行高 ≥1.5。
- 所有可点区域 ≥44×44px。

**Don't**
- 不用紫色/粉色渐变、霓虹色、玻璃拟态重模糊、毛玻璃背景。
- 不用游戏化元素：连续打卡、积分、等级、彩带动画、未读红点。
- 不用「智能推荐 / AI 洞察 / 魔法棒 / 大脑」等算法暗示的图标与文案——本产品明确不做算法。
- 不用纯黑文字 `#000` 配纯白底；用墨色 `#302B27` 配暖米白。
- 不做社交 App 式的信息流密度与头像墙；这里没有「动态」，只有「记录」。
- 不用颜色作为唯一区分（尤其 待确认 与 双向 都偏蓝绿，必须靠文字与图标区分）。
- 阴影不得深于 `rgba(48,43,39,0.16)`，不得出现彩色阴影。
- 禁止状态自动变化动画（如「已失效」自动淡出）——所有数据变化由用户显式确认。

## 2. 色彩系统（Color System）

### 2.1 设计思路

所有颜色先以 HSL 定义「意图」，再展开为可落地的 HEX。中性色统一带极低的暖色调（H≈25–40°，S≈8–20%），形成纸感底色；强调色走冷色（墨蓝 H214°）与之对比。每个语义色提供三档：**soft（徽章/浅底）、base（实心图标/圆点）、ink（浅底上的文字）**，确保对比度全部达到 WCAG AA。

> 对比度均经实测计算。徽章文字在其浅底上 ≥5:1，正文文字在页面底上 ≥5.4:1。

### 2.2 主色 · 墨蓝（Primary / Ink Blue）

| Token | HSL | HEX | 用途 | 白底对比度 |
| --- | --- | --- | --- | --- |
| `--color-primary-50` | 214, 48%, 96% | `#F0F4FA` | 极浅蓝底、hover 背景 | 1.10 |
| `--color-primary-100` | 214, 48%, 92% | `#E1E9F4` | 选中态芯片底色、头像占位底 | 1.22 |
| `--color-primary-200` | 214, 45%, 84% | `#C4D4E9` | 选中态描边、分隔强调 | 1.51 |
| `--color-primary-500` | 214, 48%, 38% | `#325B8F` | **主色**：主按钮、激活 Tab、链接 | 6.93 ✅ |
| `--color-primary-600` | 214, 50%, 32% | `#294C7A` | 主按钮 hover | 8.72 ✅ |
| `--color-primary-700` | 214, 52%, 27% | `#214069` | 主按钮 pressed、选中态文字 | 10.49 ✅ |

主色 `#325B8F` 配白色文字对比度 6.93:1，通过 AA（接近 AAA）。

### 2.3 中性色 · 暖灰纸系（Neutral）

| Token | HSL | HEX | 用途 | 白底对比度 |
| --- | --- | --- | --- | --- |
| `--color-neutral-0` | — | `#FFFFFF` | 卡片/弹层表面 | — |
| `--color-neutral-50` | 40, 20%, 98% | `#FBFAF9` | **页面底色**（暖米白） | 1.04 |
| `--color-neutral-100` | 40, 16%, 95% | `#F4F3F0` | 次级填充、标签芯片底 | 1.11 |
| `--color-neutral-200` | 35, 14%, 90% | `#E9E6E2` | 柔和分隔线 | 1.24 |
| `--color-neutral-300` | 30, 12%, 83% | `#D9D4CE` | 边框、输入框描边 | 1.47 |
| `--color-neutral-400` | 25, 9%, 65% | `#AEA49E` | 禁用图标、占位插画描边（非文字） | 2.44 |
| `--color-neutral-500` | 25, 8%, 45% | `#7C716A` | 占位符、辅助说明文字 | 4.74 ✅ |
| `--color-neutral-600` | 25, 8%, 40% | `#6E655E` | 次级正文 | 5.70 ✅ |
| `--color-neutral-700` | 25, 8%, 30% | `#534B46` | **正文主色** | 8.53 ✅ |
| `--color-neutral-900` | 25, 10%, 17% | `#302B27` | **标题 / 墨色**（近乎黑但不刺眼） | 14.00 ✅ |

正文 `#534B46` 在页面底 `#FBFAF9` 上对比度 8.18:1；标题 `#302B27` 为 13.42:1。

### 2.4 语义色与四种好友状态映射（Semantic）

| 语义 | 状态 | soft 浅底 | base 实心/圆点 | ink 浅底文字 | ink 在 soft 上对比度 |
| --- | --- | --- | --- | --- | --- |
| 成功 Success | **双向** | `#EAF6F0` | `#267E55` | `#1C6945` | 6.00 ✅ |
| 警告 Warning | **单向** | `#FEF4E7` | `#DD870E` | `#A24F07` | 5.28 ✅ |
| 信息 Info | **待确认** | `#E9F4FB` | `#2280C3` | `#1767A1` | 5.38 ✅ |
| 失效 Invalid | **已失效** | `#FAF0F0` | `#965954` | `#965954` | 4.87 ✅ |
| 危险 Danger | 仅用于破坏性操作 | `#FCEFEE` | `#DC3428` | `#BA261C` | 6.21（白底）✅ |
| 重要 Important | 「重要」星标 | `#FEF7E7` | `#E2A412` | `#965D08` | 5.09 ✅ |

**关键说明**
- **`已失效` 用低饱和砖红 `#965954`，不用危险红 `#DC3428`。** 因为「已失效」是默认从主列表隐藏的历史状态，需要弱化而非报警；纯危险红 `#DC3428` 严格保留给「删除人物 / 覆盖备份」等破坏性确认，避免用户形成"红色=常态状态"的钝化。
- **`待确认`（蓝）与 `双向`（绿）、主色（墨蓝）的区分**：待确认徽章用亮天蓝底 + 时钟图标 + 文字「待确认」，主色是深墨蓝实心，使用场景（徽章 vs 按钮）与明度都不同，不会混淆。
- **`重要` 星标用暖金 `#E2A412`**：与「单向」琥珀色相近，但靠**形状**（实心五角星 ★ vs 圆点徽章）区分，语义不会混。
- 所有状态徽章必须带文字；颜色只是加速识别的冗余通道。

## 3. 字体系统（Typography）

### 3.1 字体族

本地优先、离线可用，**不加载任何 Web Font**（隐私 + 性能考虑），使用系统字体栈：

```css
--font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
             "Hiragino Sans GB", "Microsoft YaHei", "Source Han Sans SC",
             "Noto Sans CJK SC", sans-serif;
--font-numeric: var(--font-sans); /* 日期、计数统一加 font-variant-numeric: tabular-nums */
```

- 中英文混排：英文/数字用系统拉丁字体，中文用系统中文字体，不做强制替换。
- 数字（人数、日期、计数）使用 `tabular-nums`，避免列表跳动。

### 3.2 字号阶梯

以移动端为基准，比例约 1.2–1.25。

| 层级 | 字号 / 行高 | 字重 | 颜色 Token | 典型用途 |
| --- | --- | --- | --- | --- |
| Display | 28 / 36px | 700 | `--text-heading` | 我的页大标题、引导页 |
| H1 | 22 / 30px | 700 | `--text-heading` | 页面标题（人脉/查询/关系网/我的） |
| H2 | 18 / 26px | 600 | `--text-heading` | 区块标题（TA 认识的人、筛选结果） |
| H3 | 16 / 24px | 600 | `--text-heading` | 人物姓名、卡片主标题 |
| Body | 15 / 22px | 400 | `--text-primary` | 正文、列表主信息（移动端） |
| Body-lg | 16 / 24px | 400 | `--text-primary` | 正文（桌面宽屏 ≥1024 提升一档） |
| Label | 14 / 20px | 500 | `--text-secondary` | 表单标签、次级信息 |
| Caption | 12 / 18px | 400 | `--text-placeholder` | 辅助说明、更新时间、中间人 |
| Micro | 11 / 16px | 600 | 语义 ink | 徽章、芯片、Tab 文字 |

**字重只用 4 档**：400 / 500 / 600 / 700。禁止 300 细体（中文发虚）与 800/900 粗黑。
**行高规则**：正文 ≥1.45，标题 1.3–1.4，徽章/芯片 1.3。中文不加字间距（`letter-spacing: 0`）；英文大标题可 `-0.2px`。
**换行**：中文正文不设 `text-align: justify`。

## 4. 布局与栅格（Layout & Grid）

### 4.1 间距体系

- 基础栅格 **4pt**，实际节奏 **8pt**。
- 间距 Token：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48` px。
- 页面左右安全边距：移动端 **16px**；桌面内容区外边距 24px。
- 卡片内边距：**16px**（移动端与桌面一致）。
- 卡片之间间距：**12px**（列表）/ **16px**（网格）。
- 区块之间间距：**24px**（移动端）/ **32px**（桌面）。

### 4.2 圆角

| Token | 值 | 用途 |
| --- | --- | --- |
| `--radius-xs` | 4px | 极小标签、色块 |
| `--radius-sm` | 8px | 按钮、输入框、芯片 |
| `--radius-md` | 12px | 人物卡片、列表卡片 |
| `--radius-lg` | 16px | 弹窗、底部抽屉顶部 |
| `--radius-pill` | 999px | 徽章、头像、FAB |

### 4.3 阴影层级（暖调，勿用纯黑）

```css
--shadow-1: 0 1px 2px rgba(48,43,39,.04), 0 1px 3px rgba(48,43,39,.03); /* 卡片，配合 1px 描边 */
--shadow-2: 0 4px 16px rgba(48,43,39,.10);   /* 下拉菜单、Popover */
--shadow-3: 0 12px 32px rgba(48,43,39,.16);  /* 弹窗、底部抽屉、FAB */
```

卡片默认 = 描边 `1px solid #E9E6E2` + `--shadow-1`。禁止更重的阴影。

### 4.4 响应式断点与导航适配

| 断点 | 布局 | 导航 |
| --- | --- | --- |
| `< 768px`（手机，主场景） | 单列，左右 16px 边距 | **底部 Tab Bar 固定**，56px + 安全区 |
| `768–1023px`（平板/横屏） | 单列，内容最大宽 640px 居中 | 底部 Tab Bar 固定 |
| `≥ 1024px`（桌面宽屏） | 左侧导航 216px + 内容区（最大宽 960px 居中）；顶部可保留页标题 | 4 个 Tab 平移为**左侧竖向导航**（图标+文字），底部 Tab 隐藏 |

> 桌面端采用「左侧导航」是建议方案：保持 4 个目的地的语义不变，同时比居中底部 Tab 更符合工具型产品的宽屏使用习惯。此点请体验与前端成员在 Phase 2/3 确认，但视觉规格（图标、激活态颜色）保持一致。

### 4.5 安全区与可点区域

- 底部 Tab Bar：`padding-bottom: env(safe-area-inset-bottom)`。
- 页面内容底部留白：`calc(72px + env(safe-area-inset-bottom))`，避免被 Tab Bar 与 FAB 遮挡。
- 顶部：刘海设备 sticky 头部使用 `padding-top: env(safe-area-inset-top)`。
- 所有可点击元素最小 **44×44px**；列表行最小高度 **64px**。
- FAB 位置：`right: 16px; bottom: calc(72px + env(safe-area-inset-bottom))`。

## 6. 图标与插画风格（Icon & Illustration）

### 6.1 图标

- **线性描边图标**，24×24 基准网格，常用 20px / 24px 两档。
- 描边宽度 **1.75px**（移动端）/ **1.5px**（桌面），`stroke-linecap: round`、`stroke-linejoin: round`，`currentColor`。
- 默认线性，仅激活态可填充或着色为墨蓝；不做双色渐变图标。
- 需要的图标清单：人物、搜索、筛选、关系网（节点连线）、我、加号、箭头、勾选圈、单向（双向箭头/半环）、待确认（时钟）、已失效（斜杠圈）、星标、下载、上传、锁（隐私）、更多、编辑、删除、关闭、刷新（复查）。
- 状态图标始终与文字标签同时出现。

### 6.2 空状态插画

- 方向：**「安静的手账线稿」**——两三个抽象人形节点由一条细线相连，其中一个是空心圆占位，暗示「关系还没连上 / 还没记录」。
- 线条：暖灰 `#D9D4CE`，重要连接点用墨蓝 `#325B8F` 点缀，局部填充 `#F4F3F0`。
- 风格：扁平、纯线性、无渐变、无 3D、无人脸五官、无吉祥物、无表情符号。
- 尺寸 120–160px，随空状态标题语义微调（查询无结果可把连线画成断开的两段）。
- 避免：卡通人物、夸张表情、彩色大插画、动画循环。

## 8. 交接说明与避免返工清单

**给体验/信息架构成员**：4 个 Tab 在桌面端建议转为左侧导航；空状态的四种文案已在 5.7 给出；状态切换与二次确认的触发时机由体验流程决定，本规范只规定其视觉表现。

**给前端成员**：
1. 先把第 7 节 Tokens 落成 `:root` 变量，所有组件只引用语义别名，禁止散落 HEX。
2. 状态徽章务必「颜色 + 圆点 + 文字」三通道，且 `已失效` 用砖红 `#965954`、`删除` 才用 `#DC3428`，不要混用。
3. 安全区（`env(safe-area-inset-*)`）与 `tabular-nums` 是最容易漏的两点，务必在组件层统一处理。

**最容易返工的 5 件事**：渐变/毛玻璃、游戏化红点与动效、算法暗示图标、颜色单独表意、卡片套卡片的多层阴影——以上全部禁止。
